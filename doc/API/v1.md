# API v1 (Beta)

!!! warning "Beta"
    The v1 API is in **beta**. Endpoints and behaviour can change without
    notice during active development. The full endpoint documentation
    comes later. For now, this page gives the basics and tells how to extend
    it. The stable API with full documentation is [v0](index.md).

    The v1 API is disabled by default. To enable it, use
    `lnms config:set api.v1.enabled true`, or the web UI under
    **Settings → API → API v1 (Beta)**. When it is disabled, all `/api/v1`
    endpoints return 404, and the web UI does not show v1 token management.

## Overview

The v1 API uses the `/api/v1` prefix. It is built on
[Laravel Restify](https://restify.binarcode.com/) with
[Sanctum](https://laravel.com/docs/sanctum) bearer-token authentication.

## Authentication

Most v1 endpoints need a personal access token, sent as a bearer token:

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' https://librenms.org/api/v1/system
```

Create a v1 token in the web interface at `/api-access/`, in the
**API v1 tokens** section.

## Available endpoints

| Method | Path             | Auth          | Description                                      |
|--------|------------------|---------------|--------------------------------------------------|
| `GET`  | `/api/v1/health` | none (public) | Rate-limited readiness probe.                    |
| `GET`  | `/api/v1/system` | bearer token  | Application version and database row statistics. |

We add more endpoints as the v1 API develops.

### Health

`GET /api/v1/health` is public. Thus, it can report a failure also when
token authentication from the database is not available. Its response is
generic by design: it does not identify dependencies, and it does not include exception
messages, application details, or user information. The limit is
60 requests each minute for each client.

A healthy response returns HTTP 200:

```json
{
  "meta": {
    "status": "healthy"
  }
}
```

A dependency that is not available returns a generic HTTP 503:

```json
{
  "errors": [
    {
      "status": "503",
      "title": "Service Unavailable",
      "detail": "A required service is unavailable."
    }
  ]
}
```

### System

`GET /api/v1/system` needs a bearer token. It returns the application
identity and selected table row counts:

```json
{
  "meta": {
    "application": {
      "name": "LibreNMS",
      "version": "26.7.0"
    },
    "statistics": {
      "devices": 42,
      "ports": 512,
      "users": 3
    }
  }
}
```

If the database is not available during authentication, or when the system
collects statistics, the endpoint returns the same generic JSON:API 503 error as
the health endpoint. The response never includes database connection details.

## Adding custom endpoints

There are two locations to add v1 functions. The correct location is
related to your need: a plain route, or a full CRUD resource.

### 1. Custom (non-repository) endpoints

Some routes are not standard CRUD resources: health checks, actions,
reports, and so on. To declare them, replace `routes()` on a class in
`app/Restify/`. Restify finds these classes and applies the configured
v1 prefix and middleware. Point the route at an invokable controller in
`app/Http/Controllers/Api/V1/`.

```php
// app/Restify/ExampleRepository.php
namespace App\Restify;

use App\Http\Controllers\Api\V1\ExampleController;
use Illuminate\Routing\Router;

class ExampleRepository extends Repository
{
    public static string $uriKey = '';

    public static function routes(Router $router, array $attributes, $wrap = true): void
    {
        // Routes are authenticated by default.
        $router->get('example', ExampleController::class)
            ->name('api.v1.example');

        // Authentication must be explicitly removed for a public route.
        $router->get('public-example', ExampleController::class)
            ->withoutMiddleware('auth:sanctum')
            ->name('api.v1.public-example');
    }
}
```

A minimal controller:

```php
// app/Http/Controllers/Api/V1/ExampleController.php
namespace App\Http\Controllers\Api\V1;

use App\Http\Controllers\Controller;
use Illuminate\Http\JsonResponse;

class ExampleController extends Controller
{
    public function __invoke(): JsonResponse
    {
        return response()->json(['meta' => ['message' => 'example']]);
    }
}
```

Guidelines:

- Place controllers in `app/Http/Controllers/Api/V1/`.
- Routes inherit `auth:sanctum`. Remove it with
  `->withoutMiddleware('auth:sanctum')` only for endpoints that must be
  public, such as the health probe.
- Give custom routes a unique `api.v1.*` name.

### 2. Restify repository (CRUD) resources

For standard create/read/update/delete access to a model, add a Restify
repository in `app/Restify/`:

```php
// app/Restify/DeviceRepository.php
namespace App\Restify;

use App\Models\Device;

class DeviceRepository extends Repository
{
    public static string $model = Device::class;
}
```

Restify finds the repository and makes the standard resource routes
(index, show, store, update, destroy) under `/api/v1` automatically. Refer to the
[Laravel Restify documentation](https://restify.binarcode.com/) for how to
define repositories, fields, and authorization.

### After changing routes

The system caches the route and the config at container start. Thus, after you
add or change endpoints, clear the caches:

```bash
php artisan route:clear
php artisan config:clear
```

Check the result with `php artisan route:list --path=api/v1`.
