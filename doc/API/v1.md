# API v1 (Beta)

!!! warning "Beta"
    The v1 API is in **beta**. Endpoints and behaviour may change without
    notice while it is under active development. The stable API remains
    [v0](index.md).

    The v1 API is disabled by default. Enable it with
    `lnms config:set api.v1.enabled true`, or in the web UI under
    **Settings → API → API v1 (Beta)**. When disabled, all `/api/v1`
    endpoints return 404.

## Overview

The v1 API is served under the `/api/v1` prefix and is built on
[API Platform](https://api-platform.com/docs/laravel/) with
[Sanctum](https://laravel.com/docs/sanctum) bearer-token authentication.

Resources negotiate the response format from the `Accept` header:

| `Accept`                                    | Extension  | Response                                                 |
|---------------------------------------------|------------|----------------------------------------------------------|
| _(none)_, `*/*`, `application/vnd.api+json` | `.jsonapi` | [JSON:API](https://jsonapi.org/), with pagination totals |
| `application/json`                          | `.json`    | plain JSON                                               |
| `application/ld+json`                       | `.jsonld`  | JSON-LD with Hydra collection metadata                   |
| `application/hal+json`                      | `.jsonhal` | [HAL](https://stateless.group/hal_specification.html)    |

The extension is easier in a browser: `/api/v1/devices.json`,
`/api/v1/devices/1.jsonld`.

Resource errors are returned as `application/problem+json`.

## Authentication

Most v1 endpoints require a personal access token sent as a standard Bearer token:

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' https://librenms.org/api/v1/system
```

A browser that is logged in to the web interface can also use the API with
its session, which is handy for opening an endpoint directly. The same rules
apply as for a web page: two-factor verification must be complete, and any
request that changes data needs the CSRF token.

Create an API token from the web interface at `/api-access/` (**Settings → API Settings → API Access**). Note that `X-Auth-Token` is only supported on API v0 endpoints; API v1 strictly requires the `Authorization: Bearer` header.

## Available endpoints

| Method | Path             | Auth          | Description                                      |
|--------|------------------|---------------|--------------------------------------------------|
| `GET`  | `/api/v1/health` | none (public) | Rate-limited readiness probe.                    |
| `GET`  | `/api/v1/system` | bearer token  | LibreNMS version and how much of it you may access. |
| `GET`  | `/api/v1/docs`   | bearer token  | Interactive reference in a browser, OpenAPI description for other clients. |

The resources (devices, locations and system) are listed in the [reference](#reference)
below.

More endpoints will be added as the v1 API matures.

### Health

`GET /api/v1/health` is public so it can report a failure even when
database-backed token authentication is unavailable. Its response is
deliberately generic: it does not identify dependencies or include exception
messages, application details, or user information. Requests are limited to
60 per minute per client.

A healthy response returns HTTP 200:

```json
{
  "meta": {
    "status": "healthy"
  }
}
```

An unavailable dependency returns a generic HTTP 503:

```json
{
  "errors": [
    {
      "status": "503",
      "title": "Service Unavailable",
      "detail": "A required service is unavailable."
    }
  ]
}
```

### System

`GET /api/v1/system` returns the LibreNMS version and how many devices, ports
and sensors you may access. It is a resource like the others, so it is in the
[reference](#reference) and comes in every format:

```json
{
  "name": "LibreNMS",
  "version": "26.7.0",
  "device_count": 42,
  "port_count": 512,
  "sensor_count": 96
}
```

## Field names

Field names are lowercase `snake_case`, and mostly the database column names.
Where a column does not follow these rules, the API renames it:

- No capitals: `sys_name`, `sys_object_id`, `bgp_local_as`.
- A resource does not repeat its own name in its fields: a device has `id`,
  not `device_id`, and a location has `name`. A reference to another resource
  keeps that resource's name, such as `location_id`.
- Names are singular: a device has `feature` and `note`.

Filters and sorting use the same names as the response, for example
`/api/v1/devices?hostname=core&order[hostname]=asc`. Fields that are `null`
are left out of the response.

## Relations

A resource refers to another one by its id: a device has `location_id`. Fetch
the other resource with a request of its own, `/api/v1/locations/{id}`.

The devices at a location are a list of their own,
`/api/v1/locations/{id}/devices`, with the same filters, sorting and pagination
as `/api/v1/devices`.

## Permissions

Resources follow the same permissions as the rest of LibreNMS. A user without
global read access only gets the devices assigned to them, and a device they
cannot access is reported as not found.

## Adding to the API

### Resources

A resource is an Eloquent model with an `#[ApiResource]` attribute; see
`app/Models/Device.php` and the
[API Platform documentation](https://api-platform.com/docs/laravel/). API
Platform exposes every column of the model, and every relation to another
resource, so:

- Turn off what must not be public with
  `#[ApiProperty(property: 'column', readable: false, writable: false)]`.
  Do this for every new sensitive column on a model that is a resource.
- Rename columns that do not follow [Field names](#field-names) with
  `#[ApiProperty(property: 'column', serialize: new SerializedName('name'))]`.
- The model needs a `hasAccess` scope. `App\Api\AccessExtension` applies it
  to the query for the requested resource, and refuses a model without one.
- That does not cover relations, so resources expose none. Turn a relation to
  another resource off with `readable: false`, keep its `_id` column, and add a
  route of its own where a list is needed.
- The model's policy decides who may use the endpoints (`viewAny`, `view`).
- Regenerate the reference after any change, and commit the result:

```bash
lnms api:openapi:export -o doc/API/v1-openapi.json
```

API Platform caches what it knows about the resources. Clear it after changing
one:

```bash
lnms cache:clear file
```

### Resources that are not a table

A resource that is computed rather than stored is a plain class in
`app/ApiResource/` with a state provider next to it; see `System.php` and
`SystemProvider.php`.

### Plain routes

`/api/v1/health` is a plain route in `routes/api.php`, not a resource: it has
to answer without a database or a token, and API Platform needs the database
to load. Prefer a resource for anything else, so that it is documented.
