# API v2 (Beta)

!!! warning "Beta"
    The v2 API is in **beta**. Endpoints and behaviour may change without
    notice while it is under active development. The stable, fully documented
    API remains [v0](index.md); [v1](v1.md) is a separate beta API and is not
    replaced by this one.

    Unlike v1, v2 has no on/off setting: it is reachable by anyone holding an
    API token, subject to the same per-device and per-port permissions as the
    rest of LibreNMS.

## Overview

The v2 API is served under the `/api/v2` prefix and uses
[Sanctum](https://laravel.com/docs/sanctum) bearer-token authentication.

It is built with [API Platform](https://api-platform.com/docs/laravel/):
endpoints are generated from the Eloquent models, along with the OpenAPI
description, pagination, filtering and error handling.

API Platform negotiates the response format from the `Accept` header:

| `Accept`                   | Response                               |
|----------------------------|----------------------------------------|
| _(none)_ or `*/*`          | plain JSON                             |
| `application/json`         | plain JSON                             |
| `application/ld+json`      | JSON-LD with Hydra collection metadata |
| `application/vnd.api+json` | JSON:API                               |

Errors are returned as `application/problem+json`.

## Authentication

Create a token as described under [Using the API](index.md), then send it as a
standard Bearer token. `X-Auth-Token` is only supported on v0; v2 requires the
`Authorization: Bearer` header.

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' https://librenms.org/api/v2/devices
```

## Field names

Field names are normalised across the endpoints:

- A resource does not repeat its own name in its fields: the device's
  `device_id` and the port's `port_id` are both `id`, and a port's
  `port_descr_*` fields are `descr_*`.
- A reference to another resource keeps that resource's name, so a port still
  carries `device_id`.
- Names are singular: a device has `feature` and `note`, a port has
  `descr_note`.
- The SNMP names are left exactly as the MIBs spell them, so `ifName`,
  `ifOperStatus`, `ifInOctets` and friends keep their capitals and their
  plurals.

Filters and sorting use the same names as the response.

## Available endpoints

| Method | Path                                | Description                               |
|--------|-------------------------------------|-------------------------------------------|
| `GET`  | `/api/v2/devices`                   | List devices.                             |
| `GET`  | `/api/v2/devices/{id}`              | Show a single device.                     |
| `GET`  | `/api/v2/devices/{device_id}/ports` | List the ports of one device.             |
| `GET`  | `/api/v2/ports`                     | List ports.                               |
| `GET`  | `/api/v2/ports/{id}`                | Show a single port.                       |
| `GET`  | `/api/v2/docs`                      | OpenAPI description of the whole API.     |

More endpoints will be added as the v2 API matures.

### Devices

`GET /api/v2/devices` lists the devices the token's user may see: users
without the global `viewAll` device permission only get the devices assigned
to them, and `GET /api/v2/devices/{id}` returns 404 for a device they cannot
access.

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' https://librenms.org/api/v2/devices
```

```json
[
  {
    "id": 1,
    "hostname": "switch.example.com",
    "sysName": "switch",
    "display": "switch.example.com",
    "ip": "192.0.2.10",
    "os": "ios",
    "type": "network",
    "status": true,
    "last_polled": "2026-09-16T09:12:04+00:00"
  }
]
```

Null attributes are omitted. The SNMP credentials stored on the device
(`community`, `authname`, `authpass`, `cryptopass`, ...) are never returned.

Collections are paginated, 50 devices per page by default:

| Parameter      | Description                  |
|----------------|------------------------------|
| `page`         | Page number, starting at 1.  |
| `itemsPerPage` | Devices per page, up to 500. |

The hydra (`application/ld+json`) and JSON:API representations carry the total
count and the links to the next and previous pages; plain JSON returns the
page as a bare array.

These filters are available, and can be combined:

| Parameter                                                         | Match    |
|-------------------------------------------------------------------|----------|
| `hostname`, `sysName`, `display`, `hardware`, `serial`, `version` | contains |
| `os`, `type`, `location_id`, `poller_group`                       | exact    |
| `status`, `disabled`, `ignore`                                    | boolean  |
| `last_polled[eq]`, `last_polled[gt]`, `last_polled[gte]`, `last_polled[lt]`, `last_polled[lte]` | date |

Sort with `order[<field>]=asc|desc`, on `id`, `hostname`, `sysName`,
`display`, `os`, `type`, `status`, `uptime`, `inserted`, `last_polled`,
`last_discovered` or `last_ping`.

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' \
  'https://librenms.org/api/v2/devices?os=ios&status=true&order[hostname]=asc'
```

A device's ports are at `/api/v2/devices/{device_id}/ports`, see below.

The full, generated description of every parameter and field is available
from `/api/v2/docs` with `Accept: application/vnd.openapi+json`. Point a
Swagger UI or similar at it; the UIs bundled with API Platform are turned off
because their assets are not published into LibreNMS's web root.

### Ports

Ports are filtered by the port permissions: a user sees the ports of the
devices assigned to them plus any port assigned to them directly, and a port
they may not access returns 404.

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' https://librenms.org/api/v2/ports
```

```json
[
  {
    "id": 12,
    "device_id": 1,
    "ifIndex": 10101,
    "ifName": "Gi0/1",
    "ifAlias": "uplink to core",
    "ifType": "ethernetCsmacd",
    "ifSpeed": 1000000000,
    "ifOperStatus": "up",
    "ifAdminStatus": "up",
    "ifInOctets_rate": 1024,
    "ifOutOctets_rate": 2048
  }
]
```

The counter bookkeeping columns (`_prev`, `_delta`) are not returned; the
`_rate` values are. Pagination works exactly as it does for devices.

These filters are available, and can be combined:

| Parameter                                     | Match    |
|-----------------------------------------------|----------|
| `ifName`, `ifDescr`, `ifAlias`, `portName`    | contains |
| `device_id`, `ifIndex`, `ifType`, `ifOperStatus`, `ifAdminStatus`, `ifVlan` | exact |
| `ignore`, `disabled`, `deleted`               | boolean  |

Sort with `order[<field>]=asc|desc`, on `id`, `device_id`, `ifIndex`,
`ifName`, `ifAlias`, `portName`, `ifType`, `ifSpeed`, `ifOperStatus`,
`ifAdminStatus`, `ifLastChange`, `ifInOctets_rate`, `ifOutOctets_rate` or
`poll_time`.

#### The device a port belongs to

Every port carries its `device_id`, and the ports of one device are a
sub-resource of that device:

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' \
  'https://librenms.org/api/v2/devices/1/ports?ifOperStatus=up'
```

It takes the same filters, sorting and pagination as `/api/v2/ports`, and is
the same thing as `/api/v2/ports?device_id=1`.

The port resource deliberately does not serialize the device object itself:
only JSON-LD renders a related resource as a usable IRI, plain JSON returns an
empty object for it and JSON:API puts it under `attributes` with a `self` link
pointing back at the port.

## Adding resources

Resource endpoints are generated from an Eloquent model. Add `#[ApiResource]`
to it and API Platform registers the operations under `/api/v2`, generates the
OpenAPI description and handles pagination, content negotiation and errors.
`app/Models/ApiDevice.php` is the worked example; see the
[API Platform Laravel documentation](https://api-platform.com/docs/laravel/)
for everything the attributes can do.

Guidelines:

- **Put the resource on a subclass.** `ApiDevice extends Device` carries the
  API attributes and nothing else, which keeps them out of a model that is
  already 1500 lines and, more importantly, gives the resource its own
  `$visible`.
- **Serialize explicitly.** API Platform takes a resource's field list from
  the table schema, so a model without an allow-list exposes every column.
  `$visible` on the subclass is that allow-list: name the columns the API may
  return and anything else, a column a later migration adds included, stays
  server-side. It has to be the subclass because `$visible` also drives
  `toArray()`, which feeds the v0 API, the legacy `$device` array in
  `PollDevice`/`DiscoverDevice` and the alert payload. Add an
  `#[ApiProperty(..., serialize: new SerializedName(...))]` where a column
  name does not follow the conventions above.
- **`#[UsePolicy]`** is needed on the subclass: Laravel resolves policies by
  class name, so `ApiDevice` would otherwise have none and every request would
  be denied.
- **`policy:`** names the ability checked against the model's
  [policy](https://laravel.com/docs/authorization#creating-policies), the same
  ones the web UI uses. Collection operations are checked against the class,
  item operations against the model that was loaded.
- **Row level permissions** are already handled: `HasAccessQueryExtension`
  applies the model's own `hasAccess` scope, the one the web UI filters with,
  to every query API Platform builds. A model with that scope needs nothing
  extra. For anything else, a class in `app/Api/QueryExtensions/` implementing
  API Platform's `QueryExtensionInterface` is picked up automatically.
- **Filters** are declared with `#[QueryParameter]` attributes on the subclass.
  Give `order[:property]` an explicit `properties:` allow-list: left to itself
  the placeholder offers every column of the table as a sort key, including
  the ones that are not serialized. A parameter for a field that carries a
  `SerializedName` has to name the column with `property:`, the way
  `order[id]` does, since the alias applies to the response only.
- Resource metadata is derived from the database schema, so registering these
  routes needs a database connection. `App\Providers\ApiPlatformServiceProvider`
  decides when that is worth paying for; see the class for the rules.

### After changing routes

Route and config are cached on container start, so clear them as described for
[v1](v1.md#after-changing-routes), then check with
`php artisan route:list --path=api/v2`.
